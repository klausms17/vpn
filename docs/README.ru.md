# Klaus VPN — инструкция

Собственный VPN-клиент для Android на самом свежем ядре **Xray** (то же ядро, что в Happ
и v2rayNG). Вставляете ключ → нажимаете кнопку → подключено. Российские сайты и
приложения работают напрямую, остальное — через VPN.

## 1. Установка приложения

1. Откройте на телефоне страницу **Releases** репозитория (github.com/klausms17/vpn → Releases).
2. Скачайте файл:
   - `KlausVPN-…-arm64-v8a.apk` — для почти всех современных телефонов;
   - `KlausVPN-…-armeabi-v7a.apk` — для старых 32-битных;
   - `KlausVPN-…-universal.apk` — если не уверены (подходит всем, но больше).
3. Откройте файл и разрешите установку из этого источника.

## 2. Сервер

Нужен VPS за границей (Нидерланды, Германия, Финляндия и т. п.): 1 ядро, 1 ГБ ОЗУ,
Ubuntu 24.04 или Debian 12. Подключитесь к нему по SSH и выполните:

```bash
curl -fsSL https://raw.githubusercontent.com/klausms17/vpn/main/server/install.sh | sudo bash
```

Скрипт сам:
- поставит последнюю версию Xray;
- создаст ключи и настроит **VLESS + REALITY + Vision** на порту 443 (основной, самый быстрый)
  и резервный **VLESS + REALITY + XHTTP** на порту 8443;
- подберёт сайт для маскировки (проверяет, что он работает по TLS 1.3);
- включит BBR (заметно быстрее на дальних и нестабильных каналах);
- выведет готовые ключи и QR-код, а также сохранит их в `/root/klausvpn-keys.txt`.

Повторный запуск **не меняет ключи** (так же обновляется Xray). Новые ключи: `RESET=1`.
Свой сайт для маскировки: `SNI=www.example.com`.

> Если репозиторий приватный, скопируйте `server/install.sh` на сервер вручную и запустите
> `sudo bash install.sh`.

## 3. Добавление ключа

Нажмите **«+»** и вставьте ключ (`vless://`, `vmess://`, `trojan://`, `ss://`, `hy2://`) или
ссылку на подписку (`https://…`). Можно вставить сразу несколько ключей, по одному на строке.
Ещё проще — в мессенджере нажать «Поделиться» на сообщении с ключом и выбрать Klaus VPN.

Кнопка «Проверить все» измеряет реальную задержку до каждого сервера (через сам VPN-протокол,
а не простой ping).

## 4. Режимы

| Режим | Что происходит |
|---|---|
| **Россия напрямую** (по умолчанию) | .ru/.рф/.su, Госуслуги, банки, Яндекс, VK, Ozon, WB и все российские IP — напрямую; остальное — через VPN |
| **Только заблокированное** | Через VPN — только сайты, заблокированные в России (YouTube, Instagram, ChatGPT и т. д.) и Telegram |
| **Всё через VPN** | Весь трафик через VPN, кроме локальной сети |

Списки российских сайтов и заблокированных ресурсов берутся из проекта runetfreedom
(обновляется каждые 6 часов). Свежая копия вшивается в каждую сборку приложения, а в
настройках есть кнопка «Обновить базы».

## 5. Российские приложения в обход VPN

Многие банки, Госуслуги и маркетплейсы ругаются или не работают, когда видят VPN. Настройка
**«Российские приложения в обход VPN»** (включена по умолчанию) полностью выводит их из
туннеля — они работают как без VPN. Список можно дополнить: Настройки → «Исключённые
приложения». Браузеры в этот список специально не входят.

## 6. Белые списки мобильного интернета

При ограничениях мобильной связи работают только одобренные (в основном российские) адреса,
и любой зарубежный сервер становится недоступен. Приложение показывает отметку
**«белый список»** у серверов, чей IP в этот список входит (данные runetfreedom).

Обходной путь — промежуточный сервер в России с IP из белого списка, который пересылает
трафик на ваш зарубежный сервер:

```bash
sudo UPSTREAM='vless://…ключ основного сервера…' bash install-relay.sh
```

Скрипт выдаст ключ ретранслятора — добавьте его в приложение как ещё один сервер.

## 7. Надёжность и батарея

- **Постоянный VPN**: Настройки → «Постоянный VPN» → включите «Постоянная VPN» и
  «Блокировать соединения без VPN». Тогда VPN сам поднимется после перезагрузки, а при сбое
  трафик не уйдёт мимо него.
- **Работа в фоне**: на Xiaomi, Huawei, Honor, Samsung, Realme разрешите приложению работать
  без ограничений батареи (Настройки → «Работа в фоне»), иначе прошивка может его выгрузить.
- Приложение ничего не делает в фоне само по себе: нет таймеров, опросов и фоновых проверок.
  Скорость считается, только пока открыт экран приложения.

## 8. Что сделано для стабильности и безопасности

| Типичная проблема самодельных VPN | Как решено |
|---|---|
| Трафик ядра зацикливается в собственный туннель | Приложение всегда исключено из своего туннеля |
| Открытый локальный SOCKS/HTTP-порт — по нему приложения вычисляют VPN и IP сервера | Никаких локальных портов: ядро читает TUN напрямую |
| Утечки DNS и подмена DNS провайдером | Все DNS-запросы отвечает ядро: российские домены — через Яндекс DNS напрямую, остальные — через DoH внутри VPN |
| Утечка IPv6 мимо VPN | Весь IPv6 заводится в туннель; при выключенном IPv6 такие соединения сразу отклоняются |
| «Зависание» мессенджеров при смене Wi-Fi ↔ LTE | Соединения пересоздаются сразу после смены сети |
| Утечка при смене сервера | Новый туннель поднимается до закрытия старого |
| Падение интерфейса роняет VPN | VPN работает в отдельном процессе |
| Бесконечные перезапуски при сбое | Не более 3 автоперезапусков за 5 минут, дальше — уведомление |
| Ключи попадают в облачные бэкапы | Бэкапы отключены полностью |
| Ключ виден в истории буфера обмена | Скопированный ключ помечается как секретный (Android 13+) |
| Старые ключи с `allowInsecure` перестали работать в новом Xray | Сертификат сервера автоматически закрепляется при добавлении |
| Новые REALITY-серверы отвергают старые «отпечатки» браузера (ios, edge и т. п.) | Несовместимый отпечаток автоматически заменяется на chrome |
| Устаревшие транспорты (HTTP/2, QUIC, XTLS) | Понятное сообщение при добавлении ключа, а не тихая неработоспособность |
| Нерабочий файл баз после загрузки | Базы проверяются перед заменой, замена атомарная |

Почему ваш ключ работал в Happ, но не в v2RayTun: свежий Xray-сервер с REALITY принимает
только клиентов, предлагающих постквантовый обмен ключами (X25519MLKEM768). В старых сборках
ядра этого нет — сервер молча отбрасывает такие подключения. В Klaus VPN — ядро сентября 2026.

## 9. Подпись приложения (важно для обновлений)

Чтобы новые версии устанавливались поверх старых (без удаления и потери ключей), сборки
должны подписываться одним и тем же ключом. Один раз добавьте секреты в репозиторий
(GitHub → Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | файл ключа в base64 |
| `ANDROID_KEYSTORE_PASSWORD` | пароль ключа |

Создать ключ (на компьютере с Java):

```bash
keytool -genkeypair -keystore release.jks -alias release -keyalg RSA -keysize 4096 \
  -validity 36500 -dname "CN=Klaus VPN"
base64 -w0 release.jks   # это значение для ANDROID_KEYSTORE_BASE64
```

Храните `release.jks` и пароль в надёжном месте: без них обновить установленное приложение
будет нельзя. Пока секреты не добавлены, сборки подписываются временным ключом.

## 10. Сборка и проверки

Каждое изменение автоматически:
1. прогоняет тесты ядра, включая сквозные — поднимаются настоящие Xray-серверы 13 вариантов
   (VLESS REALITY Vision/XHTTP, постквантовое шифрование, TLS WS/gRPC/HTTPUpgrade, Trojan,
   VMess, Shadowsocks 2022, Hysteria2…) и через них гоняется реальный TCP и UDP трафик;
2. проверяет время старта и расход памяти ядра;
3. собирает ядро под Android, APK (с минимизацией R8), проверяет выравнивание библиотек 16 КБ
   и публикует тестовую сборку в Releases.

## 11. iPhone

Вся логика (разбор ключей и подписок, генерация конфигурации, правила для России) находится
в общем ядре `libxray/` и собирается для iOS той же командой (`gomobile bind -target=ios`).
Для iPhone останется сделать интерфейс и системный VPN-модуль (Network Extension).
