# Kirov VPN — инструкция

Собственный VPN-клиент для Android на самом свежем ядре **Xray** (то же ядро, что в Happ
и v2rayNG). Вставляете ключ → нажимаете кнопку → подключено. Российские сайты и
приложения работают напрямую, остальное — через VPN.

## 1. Установка приложения

1. Откройте на телефоне страницу **Releases** репозитория (github.com/klausms17/vpn → Releases).
2. Скачайте файл `KirovVPN-….apk` — один для любого телефона с Android 8 и новее. В релизе
   `stable` проверенная сборка (её же раздаёт знакомым панель, раздел 12), в `build-…` —
   тестовая сборка последней правки ветки.
3. Откройте файл и разрешите установку из этого источника. Если телефон пишет
   «Приложение не установлено», а Kirov VPN уже стоит, сначала удалите старую версию
   (пока сборки подписаны временным ключом, см. раздел 9).
4. Телефон вообще не даёт поставить файл (из браузера, Telegram или «Файлов»):
   - **Samsung** — выключите на время «Автоблокировщик» (Auto Blocker): Настройки →
     Безопасность и конфиденциальность → Автоблокировщик (или поиском в настройках). На
     некоторых новых телефонах он включён с завода. Если потом включите его снова, перед
     обновлением приложения его придётся выключить ещё раз;
   - **Huawei и Honor** — мешает «Чистый режим» (Pure mode): в его предупреждении выберите
     установку всё равно или выключите режим на время (поиск в настройках: «Чистый режим»).

**Обновления.** Если подписка выдана вашей панелью (раздел 12), а на ней опубликована новая
сборка, вверху главного экрана появится карточка «Доступна новая версия …».
«Обновить» скачивает файл в браузере — его остаётся открыть и установить поверх, серверы и
настройки сохранятся (при постоянном ключе подписи, раздел 9). «Позже» прячет карточку до
следующей версии. Приложение проверяет это при открытии, не чаще двух раз в сутки.

## 2. Сервер

Нужен VPS за границей (Нидерланды, Германия, Финляндия и т. п.): 1 ядро, 1 ГБ ОЗУ,
Ubuntu 24.04 или Debian 12. Репозиторий приватный, поэтому скрипт копируется вручную:

1. Откройте на GitHub файл `server/install.sh` (ветка `main`) → кнопка **Raw** → скопируйте
   весь текст.
2. Подключитесь к серверу по SSH и выполните `nano install.sh`, вставьте текст,
   сохраните (Ctrl+O, Enter, Ctrl+X).
3. Запустите:

```bash
sudo bash install.sh
```

Скрипт сам:
- поставит последнюю версию Xray;
- создаст ключи и настроит **VLESS + REALITY + Vision** на порту 443 (основной, самый быстрый)
  и резервный **VLESS + REALITY + XHTTP** на порту 8443;
- подберёт сайт для маскировки (проверяет, что он работает по TLS 1.3);
- включит BBR (заметно быстрее на дальних и нестабильных каналах);
- будет держать соединения без трафика до 30 минут (у Xray по умолчанию 5): уведомления,
  почта и мессенджеры на телефоне не переподключаются каждые 5 минут и не будят телефон зря;
- выведет готовые ключи и QR-код, а также сохранит их в `/root/klausvpn-keys.txt`.

Повторный запуск **не меняет ключи** (так же обновляются Xray и настройки сервера из новой версии
скрипта). Параметры пишутся **после** `sudo`:

- новые ключи (старые перестанут работать): `sudo RESET=1 bash install.sh`;
- свой сайт для маскировки: `sudo SNI=www.example.com bash install.sh`.

Если на сервере уже есть настройки Xray, сделанные не этим скриптом, он остановится и ничего
не тронет. Заменить их: `sudo FORCE=1 bash install.sh` (старая настройка сохранится копией).


## 3. Добавление ключа

Нажмите **«+»** и вставьте ключ (`vless://`, `vmess://`, `trojan://`, `ss://`, `hy2://`) или
ссылку на подписку (`https://…`). Можно вставить сразу несколько ключей, по одному на строке.
Ещё проще — в мессенджере нажать «Поделиться» на сообщении с ключом и выбрать Kirov VPN.
Подписка обновляется сама при открытии приложения (не чаще раза в час); если сервер подписки
не ответил или отказал (например, из-за лимита устройств), прежние серверы остаются, а причина
видна на вкладке «Серверы».

Кнопка «Проверить все» измеряет реальную задержку до каждого сервера (через сам VPN-протокол,
а не простой ping).

## 4. Что идёт через VPN

Настраивать ничего не нужно: российские сайты и сервисы (.ru/.рф/.su, Госуслуги, банки,
Яндекс, VK, Ozon, WB и все российские IP) работают напрямую, остальное — через VPN.

Списки российских сайтов берутся из проекта runetfreedom (обновляется каждые 6 часов).
Свежая копия вшивается в каждую сборку приложения, а в настройках есть пункт
«Обновить списки» (раздел «Если что-то не работает»).

## 5. Российские приложения без VPN

Многие банки, Госуслуги и маркетплейсы ругаются или не работают, когда видят VPN. Переключатель
**«Российские сервисы»** (Настройки → «Приложения без VPN», включён по умолчанию) полностью
выводит их из туннеля — они работают как без VPN. Список можно дополнить: там же
«Другие приложения». Браузеры в этот список специально не входят.

## 6. Белые списки мобильного интернета

При ограничениях мобильной связи работают только одобренные (в основном российские) адреса,
и любой зарубежный сервер становится недоступен. Приложение показывает отметку
**«белый список»** у серверов, чей IP в этот список входит (данные runetfreedom).

Обходной путь — промежуточный сервер в России с IP из белого списка, который пересылает
трафик на ваш зарубежный сервер:

```bash
# install-relay.sh копируется на российский сервер так же, как install.sh
sudo UPSTREAM='vless://…ключ основного сервера…' bash install-relay.sh
```

Скрипт выдаст ключ ретранслятора — добавьте его в приложение как ещё один сервер.

## 7. Надёжность и батарея

- **Постоянный VPN**: Настройки → «Постоянный VPN» → включите «Постоянная VPN». Тогда VPN сам
  поднимется после перезагрузки.
  «Блокировать соединения без VPN» **не включайте**: Android тогда отключает интернет всем
  приложениям, которые работают без VPN, — банкам, Госуслугам, маркетплейсам. Если всё же
  включили, приложение предупредит об этом в уведомлении.
- **Работа в фоне**: на Xiaomi, Huawei, Honor, Samsung, Realme разрешите приложению работать
  без ограничений батареи (Настройки → «Работа в фоне»), иначе прошивка может его выгрузить.
  На Xiaomi, Huawei, Honor, OPPO, Realme, OnePlus и vivo там же есть строка «Автозапуск», она
  открывает нужный экран прошивки:
  - Xiaomi, Redmi, POCO: включите «Автозапуск», в «Контроле активности» выберите
    «Нет ограничений» и закрепите Kirov VPN в недавних приложениях (значок замка);
  - Huawei, Honor: «Запуск приложений» → Kirov VPN → «Вручную», включите все три переключателя;
  - OPPO, Realme, OnePlus и vivo: разрешите автозапуск и работу в фоне.
- **Устройства в своей Wi-Fi-сети**: если видеорегистратор, умный дом (Mi Home) или Android Auto
  не подключается, пока включён VPN, отметьте его приложение: Настройки → «Приложения без VPN» →
  «Другие приложения».
- **Автопереключение**: если сервер перестал пропускать трафик, приложение само переходит на
  другой, который отвечает (сначала из той же подписки), и пишет об этом в уведомлении, на
  главном экране и в виджете. Не больше 3 переключений за 30 минут. Если сразу после этого
  снова выбрать прежний сервер вручную, приложение уводить с него не будет. Когда выбранный
  вами сервер снова отвечает (приложение пробует его не раньше чем через 30 минут, потом всё
  реже), оно возвращается на него.
- **Сообщение о недоступном сервере**: когда автопереключение сработало, а прежний сервер
  был из подписки вашей панели (раздел 12), приложение сообщает панели, что он не отвечает
  из этой сети (не чаще раза в 30 минут на сервер). Так же — когда не отвечает ни один сервер,
  а российский сайт (ya.ru) напрямую, мимо VPN, открывается: значит, интернет у телефона есть.
  Отправляются только адрес, порт и протокол сервера, тип сети (Wi-Fi или мобильная, для
  мобильной — название оператора), отметки «перешёл на сервер из белого списка» и «не ответил
  ни один сервер», версия приложения и идентификатор подписки. Ни сайтов, ни трафика, ни
  данных телефона.
  Когда о сервере сообщат несколько человек, панель пришлёт вам оповещение в Telegram.
- С выключенным экраном приложение ничего не делает само по себе: нет таймеров и опросов.
  Связь проверяется при подключении, смене сети, открытии приложения, разблокировке телефона
  (не чаще раза в 10 минут) и, пока экран включён, если 5 минут проверок не было. При
  подключении и не чаще раза в полчаса в каждой сети проверка ещё скачивает через сервер
  64 КБ с Cloudflare: так видно операторов, которые «замораживают» соединение после первых
  килобайт.
  Трафик не подсчитывается; таймер подключения идёт, только пока открыт экран приложения.
- Если что-то не так: Настройки → «Сообщить о проблеме» — там журнал и кнопка «Копировать».
  В журнале могут быть адреса серверов, поэтому пересылайте его только тому, кому доверяете.

## 8. Что сделано для стабильности и безопасности

| Типичная проблема самодельных VPN | Как решено |
|---|---|
| Трафик ядра зацикливается в собственный туннель | Приложение всегда исключено из своего туннеля |
| Открытый локальный SOCKS/HTTP-порт — по нему приложения вычисляют VPN и IP сервера | Никаких локальных портов: ядро читает TUN напрямую |
| Утечки DNS и подмена DNS провайдером | Все DNS-запросы отвечает ядро: российские домены — через Яндекс DNS напрямую, остальные — через DoH внутри VPN |
| Утечка IPv6 мимо VPN | Весь IPv6 заводится в туннель; при выключенном IPv6 такие соединения сразу отклоняются |
| «Зависание» мессенджеров при смене Wi-Fi ↔ LTE | Соединения пересоздаются сразу после смены сети |
| Утечка при смене сервера | Новый туннель поднимается до закрытия старого |
| Падение интерфейса роняет VPN | VPN работает в отдельном процессе |
| Бесконечные перезапуски при сбое | Не более 3 автоперезапусков за 5 минут, дальше — уведомление |
| Сервер перестал отвечать, а VPN по-прежнему «Подключено» | Трафик проверяется при подключении, смене сети и, пока экран включён, раз в 5 минут (замирание после первых килобайт тоже видно); при сбое — переход на рабочий сервер |
| Ключи попадают в облачные бэкапы | Бэкапы отключены полностью |
| Ключ виден в истории буфера обмена | Скопированный ключ помечается как секретный (Android 13+) |
| Старые ключи с `allowInsecure` перестали работать в новом Xray | Сертификат сервера автоматически закрепляется при добавлении |
| Новые REALITY-серверы отвергают старые «отпечатки» браузера (ios, edge и т. п.) | Несовместимый отпечаток автоматически заменяется на chrome |
| Устаревшие транспорты (HTTP/2, QUIC, XTLS) | Понятное сообщение при добавлении ключа, а не тихая неработоспособность |
| Нерабочий файл баз после загрузки | Базы проверяются перед заменой, замена атомарная |

Почему ваш ключ работал в Happ, но не в v2RayTun: свежий Xray-сервер с REALITY принимает
только клиентов, предлагающих постквантовый обмен ключами (X25519MLKEM768). В старых сборках
ядра этого нет — сервер молча отбрасывает такие подключения. В Kirov VPN — ядро сентября 2026.

## 9. Подпись приложения (важно для обновлений)

Чтобы новые версии устанавливались поверх старых (без удаления и потери ключей), сборки
должны подписываться одним и тем же ключом. Один раз добавьте секреты в репозиторий
(GitHub → Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | файл ключа в base64 |
| `ANDROID_KEYSTORE_PASSWORD` | пароль ключа |

Создать ключ на Windows:

1. Поставьте Java: https://adoptium.net → Temurin, последняя LTS-версия → установщик `.msi`
   для Windows x64, всё по умолчанию.
2. Откройте **новое** окно PowerShell (Пуск → «PowerShell») и выполните:

   ```powershell
   keytool -genkeypair -keystore "$HOME\release.jks" -alias release -keyalg RSA -keysize 4096 -validity 36500 -dname "CN=Kirov VPN"
   ```

   Программа дважды спросит пароль (не меньше 6 символов, при вводе не виден): это значение
   для `ANDROID_KEYSTORE_PASSWORD`.
3. Положите ключ в буфер обмена и вставьте его (Ctrl+V) в секрет `ANDROID_KEYSTORE_BASE64`:

   ```powershell
   [Convert]::ToBase64String([IO.File]::ReadAllBytes("$HOME\release.jks")) | Set-Clipboard
   ```

То же на Linux или Mac:

```bash
keytool -genkeypair -keystore release.jks -alias release -keyalg RSA -keysize 4096 \
  -validity 36500 -dname "CN=Kirov VPN"
base64 -w0 release.jks   # это значение для ANDROID_KEYSTORE_BASE64
```

Храните `release.jks` и пароль в надёжном месте (например, на флешке и в менеджере паролей) и
никому их не присылайте: без них обновить установленное приложение будет нельзя. Пока секреты не
добавлены, сборки подписываются временным ключом, и у каждой он свой. Поэтому первую сборку с
постоянным ключом поверх старой не поставить: старое приложение один раз удалите и добавьте
ссылку заново, дальше обновления встают поверх.

**Проверка разработчика Google.** Google вводит обязательную регистрацию разработчиков и для
приложений, которые ставятся не из Play (developer verification: по планам Google — с сентября
2026 года в нескольких странах, по всему миру с 2027-го). Без неё сертифицированные телефоны
могут перестать устанавливать приложение. Регистрация привязана к имени пакета `com.klausms.vpn` и ключу
подписи, поэтому делайте её уже с постоянным ключом: когда появится `release.jks`,
зарегистрируйте `com.klausms.vpn` с ним в Android Developer Console, не дожидаясь, пока
проверка дойдёт до телефонов знакомых.

## 10. Сборка и проверки

Каждое изменение автоматически:
1. прогоняет тесты ядра, включая сквозные — поднимаются настоящие Xray-серверы 13 вариантов
   (VLESS REALITY Vision/XHTTP, постквантовое шифрование, TLS WS/gRPC/HTTPUpgrade, Trojan,
   VMess, Shadowsocks 2022, Hysteria2…) и через них гоняется реальный TCP и UDP трафик;
2. проверяет время старта и расход памяти ядра;
3. собирает ядро под Android, APK (с минимизацией R8), проверяет выравнивание библиотек 16 КБ
   и публикует тестовую сборку в Releases (`build-` и название ветки).

Стабильную сборку (релиз `stable`, её панель раздаёт знакомым) CI делает только по вашей
команде — см. «Раздача приложения и обновления» в разделе 12.

## 11. iPhone

Вся логика (разбор ключей и подписок, генерация конфигурации, правила для России) находится
в общем ядре `libxray/` и собирается для iOS той же командой (`gomobile bind -target=ios`).
Для iPhone останется сделать интерфейс и системный VPN-модуль (Network Extension).

## 12. Раздача знакомым: панель и подписки

Ключ из `install.sh` один на всех: его нельзя отключить одному человеку, а если сервер
заблокируют, новый ключ придётся рассылать каждому. Для раздачи знакомым есть панель
**Remnawave**: у каждого своя ссылка-подписка, по ней приложение само получает список
серверов и обновляет его. Сервер заблокировали — вы добавляете новый в панели, знакомым
ничего делать не нужно.

### Что купить

- **VPS для панели** за границей: 2 ядра, 4 ГБ ОЗУ, Ubuntu 24.04 или Debian 12. VPN на нём
  не работает — только панель и страница подписки.
- **VPS для VPN** (один или несколько) за границей, как в разделе 2. При безлимитном трафике
  главное — скорость канала и объём трафика в тарифе.
- **Домен** в зоне .com, .net, .org и т. п. Домены .ru, .su, .рф не подойдут: для них не
  выдают бесплатный сертификат HTTPS. В настройках DNS создайте две записи типа A на IP
  VPS панели, например `panel.example.com` (панель) и `sub.example.com` (подписки). Если
  домен в Cloudflare, выключите для этих записей проксирование (серое облако).

### Установка: три команды

Скрипты лежат в папке `server/remnawave/` и копируются на серверы так же, как `install.sh`
(раздел 2).

1. **Панель.** На VPS панели положите `install-panel.sh`, `klaus-panel`, `klaus-monitor.py` и
   `klaus-page.html` в одну папку и выполните:

   ```bash
   sudo PANEL_DOMAIN=panel.example.com SUB_DOMAIN=sub.example.com bash install-panel.sh
   ```

   Скрипт поставит Docker, панель, страницу подписки и Caddy (он сам получает и продлевает
   сертификаты HTTPS), создаст администратора и настроит всё для Kirov VPN: протокол
   VLESS + REALITY, название «Kirov VPN» в приложении и светлую страницу Kirov VPN
   (`klaus-page.html`), которую знакомый видит, открыв ссылку в браузере: как поставить
   приложение и добавить ссылку кнопкой «Добавить в Kirov VPN». У страницы три вкладки:
   Android, iPhone и Windows (на iPhone и Windows пока «Скоро»), нужная открывается сама.
   Приложения по той же ссылке получают список серверов. Логин и пароль от панели — в `/root/remnawave-admin.txt`. Адрес
   панели знакомым не нужен, не показывайте его: им хватает ссылки на подписку.

   Страницу панель дальше обновляет сама: раз в 15 минут берёт `klaus-page.html` из ветки
   `main` репозитория и вписывает в неё ваши `APK_URL` и `SUPPORT_URL`. Поэтому исправления
   страницы доходят до знакомых без вас, запускать ничего не нужно. Неполную страницу панель
   не возьмёт и оставит прежнюю. Выключить: `sudo PAGE_BRANCH= bash install-panel.sh`
   (останется страница из папки со скриптом); другая ветка: `PAGE_BRANCH=имя`.

   Приложение панель может раздавать сама (раздел «Раздача приложения и обновления» ниже);
   вместо этого можно указать `APK_URL=https://…` — ссылку на файл приложения, которая
   открывается без входа (например, в облачном диске): на странице подписки появится кнопка
   «Скачать приложение». Своя ссылка для связи с вами: `SUPPORT_URL=https://t.me/…` (без неё
   кнопка поддержки на странице подписки просто советует написать тому, кто дал ссылку).

2. **VPN-сервер.** На VPS панели:

   ```bash
   klaus-panel add-node de-1 203.0.113.10 DE
   ```

   (имя сервера латиницей, его IP и страна; название, которое увидят знакомые, можно задать
   так: `--title "Германия"`). Команда выведет готовую строку вида
   `sudo PANEL_IP=… SECRET_KEY='…' bash install-node.sh` — выполните её на VPS для VPN,
   скопировав туда `install-node.sh`. Скрипт поставит Docker и сервер Remnawave, включит BBR
   и откроет порт управления (2222) только для панели. Через минуту `klaus-panel list-nodes`
   покажет «на связи».

3. **Знакомый.** На VPS панели:

   ```bash
   klaus-panel add-user masha
   ```

   Команда выведет личную ссылку `https://sub.example.com/…`, QR-код и ссылку
   `klausvpn://add/…`, которая сразу открывает приложение. Ссылку отправляйте лично: по ней
   любой может пользоваться VPN. То же можно сделать без команд, с телефона: см. «Знакомый
   из веб-панели» ниже.

Повторный запуск `install-panel.sh` или `install-node.sh` ничего не ломает: ключи,
пользователи и пароли сохраняются (`install-node.sh` помнит и свои порты), а программы
обновляются до последних версий. Новые настройки VPN-серверов из новой версии скрипта
(например, соединения без трафика держатся 30 минут, как в разделе 2) `install-panel.sh`
вносит в профиль панели, и панель сама перезапускает Xray на серверах: у знакомых связь
прервётся на пару секунд. Ретранслятор (раздел 6) обновляется повторным запуском
`install-relay.sh` с тем же `UPSTREAM`. Чтобы поменять домен, `APK_URL` или `SUPPORT_URL`,
запустите `install-panel.sh` ещё раз только с новым значением (`SUPPORT_URL=` без значения
убирает ссылку), остальное он помнит. После смены `SUB_DOMAIN` старые ссылки знакомых
перестают работать: отправьте им новые (`klaus-panel link masha`).

### Знакомый из веб-панели (с телефона или компьютера)

Команды не обязательны: панель открывается в браузере и сама переходит на русский язык.

1. Откройте `https://panel.example.com` и войдите (логин и пароль — в
   `/root/remnawave-admin.txt`; браузер может их запомнить).
2. **«Пользователи»** → **«Создать пользователя»**.
3. Впишите имя латиницей (например, `masha`) и нажмите **«Создать пользователя»**. Больше
   ничего заполнять не нужно.
4. Откройте этого пользователя и нажмите **«Копировать ссылку»** — это его личная ссылка
   на подписку, отправьте её другу. Если друг рядом, покажите ему **«QR-код подписки»**.

Почему не нужно трогать остальные поля. Панель рассчитана на платные VPN, поэтому в форме
уже стоит «Дата окончания» — завтрашнее число, а «Внутренние сквады» (серверы) не выбраны. В
течение 20 секунд после создания панель сама делает подписку бессрочной и добавляет серверы
Kirov VPN (сквад `KlausVPN`); в журнале это видно так: `journalctl -u klaus-panel-users`.
Правит она только тех, кого добавили за последние двое суток, и только если у них нет
серверов или срок меньше полутора суток; остальные ваши изменения остаются как есть.
Проверить или поправить вручную: `klaus-panel tidy-users`.

### Как знакомому подключиться

1. Открыть ссылку на телефоне. Откроется страница Kirov VPN с инструкцией. На iPhone она
   пока пишет, что приложение для iPhone скоро выйдет.
2. Установить Kirov VPN (кнопка «Скачать приложение», если приложение раздаёт панель или вы
   указали `APK_URL`, или файл от вас — раздел 1). Если Samsung, Huawei или Honor не дают
   поставить файл, помогут советы из раздела 1, пункт 4 (они есть и на странице подписки).
3. Нажать **«Добавить в Kirov VPN»**: приложение откроется и предложит добавить подписку.
   Если ничего не произошло (так бывает во встроенном браузере Telegram), нажать
   «Скопировать» рядом со ссылкой, открыть Kirov VPN, нажать **«+»** и вставить. Можно и просто
   прислать ему ссылку сообщением и «Поделиться» ею в Kirov VPN.
4. Нажать большую кнопку. Дальше список серверов приложение обновляет само.

### Если сервер заблокировали

Узнаете вы об этом из Telegram (раздел «Оповещения в Telegram»): «сервер «…» не отвечает у
2 человек… похоже на блокировку». Купите новый VPS и выполните на панели:

```bash
klaus-panel add-node nl-1 198.51.100.20 NL    # и установите его, как в шаге 2
klaus-panel disable-node de-1                 # старый уходит из подписок
```

Знакомым ничего делать не нужно: приложение получит новый сервер при обновлении подписки.
Все серверы работают с одними и теми же ключами, поэтому ссылки не меняются.
`klaus-panel enable-node de-1` вернёт сервер обратно.

Сообщение, которое начинается со слов «мобильный интернет в режиме белых списков», скорее
всего не о блокировке: сервер менять и отключать не нужно. Если на него пожалуются и из других
сетей, придёт обычное сообщение (см. «Сигналы о блокировках»).

| Команда | Что делает |

| `klaus-panel link masha` | снова показать ссылку и QR-код |
| `klaus-panel disable-user masha` | отключить (подписка и VPN перестают работать), `enable-user` — вернуть |

Всё это же можно делать в самой панели: `https://panel.example.com`.

### Резервная копия

```bash
klaus-panel backup
```

Сохраняет базу (знакомые, их ссылки, серверы, ключи), настройки (в том числе Telegram и
токен GitHub) и выложенное приложение в `/root/remnawave-backups/klausvpn-panel-….tar.gz`.
Скачайте файл к себе (`scp root@IP-панели:/root/remnawave-backups/*.tar.gz .`) и храните как
пароль: в нём все ключи. Без копии при потере VPS панели всем придётся выдать новые ссылки и
заново установить серверы.

Переезд панели на новый VPS: положите рядом `install-panel.sh`, `klaus-panel`,
`klaus-monitor.py`, `klaus-page.html` и архив и выполните `sudo RESTORE=klausvpn-panel-….tar.gz bash
install-panel.sh`. Если восстановление оборвалось (нет сети, Docker Hub не отдал образы и
т. п.), выполните ту же команду ещё раз;
без `RESTORE` скрипт на таком сервере не запустится, чтобы не поставить пустую панель вместо
перенесённой. Затем направьте оба домена на новый IP и на каждом VPN-сервере выполните
`sudo PANEL_IP=новый-IP bash install-node.sh` (ключ и порты сервер помнит). Ссылки знакомых не
меняются.

### Оповещения в Telegram

Панель может писать вам в Telegram, когда с серверами что-то не так:

- **сервер потерял связь с панелью** и когда связь вернулась (сообщения самой Remnawave, на
  английском: `#nodeConnectionLost`, `#nodeConnectionRestored`; также о добавлении и
  отключении серверов);
- **сервер перестал открываться у знакомых** — похоже на блокировку (сообщение на русском,
  см. следующий раздел).

Настройка, один раз:

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, придумайте имя и адрес бота
   (например, `klaus_alerts_bot`). BotFather пришлёт токен вида `123456789:AAE…`.
2. На VPS панели выполните:

   ```bash
   klaus-panel telegram-setup 123456789:AAE…
   ```

3. Команда покажет ссылку вида `https://t.me/klaus_alerts_bot?start=код` и будет ждать:
   откройте её на телефоне и нажмите «Запустить» (или отправьте боту этот код сообщением).
   Команда запомнит этот чат, перезапустит панель и пришлёт «Kirov VPN: оповещения включены».
   Сообщения без кода не считаются: чужой человек, нашедший бота, не сможет подписаться
   на ваши оповещения.

Оповещения можно получать и в группе: откройте вторую ссылку, которую покажет команда
(`…?startgroup=код`), и выберите группу. Проверить, что всё работает: `klaus-panel telegram-test`.
Сменить чат или бота — выполнить `telegram-setup` ещё раз. Повторный запуск `install-panel.sh`
настройки сохраняет.

### Раздача приложения и обновления

Панель может сама выкладывать свежую сборку Kirov VPN по адресу
`https://sub.example.com/app/KirovVPN.apk`: на странице подписки появляется кнопка «Скачать
приложение», а установленные приложения раз в 12 часов проверяют
`https://sub.example.com/app/version.json` и, если вышла новая версия, показывают на главном
экране «Доступна новая версия» с кнопкой «Обновить» (скачивание через браузер, установка —
как обычно).

Сборки лежат в Releases репозитория. Пока он открытый, панели больше ничего не нужно; выложить
новую стабильную сборку сразу, не дожидаясь часа: `klaus-panel publish-apk`.

Если репозиторий станет закрытым, панели понадобится токен только для чтения:

1. GitHub → аватар → **Settings** → **Developer settings** → **Personal access tokens** →
   **Fine-grained tokens** → **Generate new token**.
2. Имя любое, срок — по желанию (когда истечёт, выпустите новый так же).
   **Repository access**: *Only select repositories* → `klausms17/vpn`.
   **Permissions** → **Repository permissions** → **Contents**: *Read-only*. Больше ничего.
3. Скопируйте токен (`github_pat_…`) и на VPS панели выполните:

   ```bash
   sudo GITHUB_TOKEN=github_pat_… bash install-panel.sh
   klaus-panel publish-apk
   ```

Раз в час панель сама смотрит, не вышла ли новая стабильная сборка, скачивает её, сверяет
контрольную сумму с `SHA256SUMS.txt` из того же релиза (файл с другой суммой не выкладывается)
и публикует. Заменённая версия удаляется через 13 часов (приложения проверяют обновления раз
в 12 часов), а ссылка на удалённую ведёт на текущую — кнопка «Обновить» не ведёт в пустоту.
Более старая сборка поверх новой не выкладывается. Сборки с временной подписью панель не выкладывает: поверх установленного
приложения они не встанут (сначала добавьте ключ подписи, раздел 9).

**Знакомым уходят только стабильные сборки** — релиз `stable`. Тестовые сборки `build-…`
появляются после каждой правки: их вы ставите на свой телефон, панель их не раздаёт. Когда
тестовая сборка день-другой проработала у вас без проблем, выпустите её как стабильную:

- GitHub → **Actions** → **Build** → **Run workflow** → выберите ветку, поставьте галочку
  «Стабильная сборка (stable)» → **Run workflow**. Собирается последняя правка ветки, поэтому
  делайте это, пока после проверенной сборки новых правок не было;
- или поставьте тег `v…` на проверенную правку: `git tag v1.1 КОММИТ && git push origin v1.1`.

Примерно через полчаса релиз `stable` обновится, а в течение часа после этого панель выложит
его знакомым. Номер версии у стабильной сборки свой (1.0.N по номеру запуска сборки), поэтому
обновиться предложит и вашему телефону. Пока релиза `stable` нет, панель ничего не выкладывает
(`klaus-panel publish-apk` об этом скажет).

Раздавать другой релиз: `sudo RELEASE_TAG=build-main bash install-panel.sh` (имя релиза —
`build-` и название ветки, в котором `/` заменён на `-`), вернуть стабильные —
`RELEASE_TAG=stable`. Панели, поставленные до появления `stable`, раздавали тестовые сборки
ветки `claude/compassionate-mayer-6jph8m`: при следующем запуске `install-panel.sh` они сами
переходят на `stable` и пишут об этом. Другой репозиторий — `GITHUB_REPO=владелец/имя`.

Обновление ставится поверх, только если сборки подписаны постоянным ключом (раздел 9); иначе
знакомым придётся удалить старую версию.

### Сигналы о блокировках: как это работает и что отправляют телефоны

Когда сервер перестаёт отвечать, приложение само переключается на другой. Если переключение
**удалось** (значит, интернет у телефона есть, а не отвечает именно тот сервер), приложение
один раз сообщает панели: «сервер такой-то у меня не открывается». Не чаще раза в 30 минут на
сервер с одного телефона, и только для серверов из вашей подписки. Если не ответил ни один
сервер, приложение открывает напрямую, мимо VPN, российский сайт: открылся — значит, интернет
есть, и панель тоже получает сигнал (с отметкой «не ответил ни один сервер»).

Панель ждёт сигналов от **разных** людей: если за 20 минут пожаловались хотя бы двое, вам
приходит одно сообщение в Telegram, например:

```
Kirov VPN: сервер «Германия» не отвечает у 2 человек за последние 20 мин.
Сети: Wi-Fi ×1, МТС ×1.
Панель видит сервер на связи — похоже на блокировку: добавьте новый сервер
(klaus-panel add-node …) и отключите этот (klaus-panel disable-node de-1).
Следующее сообщение об этом сервере — не раньше чем через 3 ч.
```

Если панель сама видит сервер на связи, а у людей он не открывается, — это почти наверняка
блокировка: действуйте, как в разделе «Если сервер заблокировали». Если панель тоже не видит
сервер, дело в самом VPS (выключен, не оплачен, сбой у хостера). Один человек (или один и тот
же телефон много раз) сообщение не вызовет. Порог, окно и паузу можно поменять:
`sudo REPORT_THRESHOLD=3 REPORT_WINDOW_MIN=30 REPORT_COOLDOWN_MIN=120 bash install-panel.sh`.

**Белые списки — не блокировка.** Когда мобильный интернет пускает только в белый список
(раздел 6), зарубежный сервер не открывается ни у кого из-за оператора, а приложение переходит
на ретранслятор с IP из белого списка. Если такого нет, оно пишет «Мобильный интернет в режиме
белых списков — нужен Wi-Fi». Такой сигнал приложение помечает, если телефон в
мобильной сети и мимо VPN не открывается и зарубежный сайт (Google), хотя российский
(ya.ru) открывается. Панель не считает такие сигналы блокировкой: вместо тревоги придёт одно
сообщение вида

```
Kirov VPN: мобильный интернет в режиме белых списков у 2 человек за последние 20 мин:
сервер «Германия» у них не открывается, и зарубежные сайты без VPN у них тоже не открываются.
Сети: Билайн ×1, МТС ×1.
Скорее всего, оператор открывает только сайты из белого списка: тогда не работает ни один
зарубежный сервер, и отключать или менять этот не нужно. Если на сервер пожалуются и из
других сетей, например по Wi-Fi, придёт обычное сообщение о блокировке.
Следующее такое сообщение об этом сервере — не раньше чем через 3 ч.
```

Новый зарубежный сервер в этом случае не помог бы: он был бы недоступен точно так же. Но
по одному мобильному интернету приложение не всегда отличит белые списки от блокировки
только этого сервера, поэтому сигналы из других сетей по-прежнему дают обычную тревогу.

**Что именно отправляет телефон** (и больше ничего):

| Что | Зачем |
|---|---|
| личный номер подписки (последняя часть ссылки) | проверить, что это ваш знакомый, и посчитать разных людей |
| адрес, порт и протокол сервера, который не открылся | понять, о каком сервере речь |
| тип сети: Wi-Fi, мобильная или другая | блокировки часто бывают только в мобильной сети |
| название оператора (только для мобильной сети, например «МТС») | видно, у какого оператора блокируют |
| отметка «перешёл на сервер из белого списка» | отличить ограничения мобильного оператора от блокировки сервера |
| отметка «не ответил ни один сервер» | видно, что из этой сети недоступны все серверы, а не один |
| версия приложения | — |

Не отправляются: какие сайты открывались, трафик, номер телефона, имя, местоположение,
идентификатор устройства. IP-адрес телефона видит только Caddy, а дальше он не уходит:
монитору (`klaus-monitor`) вместо него приходит 127.0.0.1 (см. следующий раздел). Чей номер
о каком сервере сообщил, хранится только в памяти и только 20 минут; в сообщения и журналы
номера не попадают.
Что монитор делал (время и названия серверов, по которым ушли сообщения):
`docker logs klaus-monitor`.

### Что панель и серверы хранят о знакомых

Только то, без чего панель не работает: имя, которое вы дали, личную ссылку и ключ, сколько
трафика израсходовано всего, когда человек последний раз был в сети, и телефоны, с которых
открывают подписку (модель, система и номер-метка, без IP-адреса: по ним работает лимит
устройств, а в `klaus-panel list-users` видно, сколько их у каждого).

Не хранится:

- **IP-адреса.** Их видит только Caddy — программа, которая принимает все запросы к панели и
  подписке. Он не пишет их в журнал и дальше не передаёт: странице подписки, панели и монитору
  блокировок вместо адреса приходит 127.0.0.1.
- **История.** Когда и каким приложением открывали подписку и сколько трафика было по дням,
  панель не записывает (настройки `SERVICE_DISABLE_SRH_RECORDS` и
  `SERVICE_DISABLE_USER_USAGE_RECORDS` в `/opt/remnawave/.env`).
- **Журнал страницы подписки.** Она записывала бы каждый запрос вместе с личной ссылкой,
  поэтому журнал у неё выключен совсем. Если она не запускается, ошибки покажет
  `cd /opt/remnawave && docker compose run --rm remnawave-subscription-page`.
- **На VPN-серверах — журнал подключений** (кто, откуда, на какие сайты): Xray его не ведёт,
  а в журнале ошибок адреса скрыты. Панель задаёт это серверам сама и возвращает при каждом
  запуске `install-panel.sh`, даже если настройку поменяли вручную.

Чего нет у вас, может быть у других: хостер VPN-сервера видит, с каких адресов к нему
подключаются, а оператор знакомого — что тот подключается к зарубежному серверу (но не то,
какие сайты он открывает).

### Лимит устройств (включается потом)

Панель уже записывает, с каких телефонов открывают подписку (столбец «устройств» в
`klaus-panel list-users`), но пока ничего не ограничивает. Включайте лимит, только когда:

1. у всех знакомых стоит версия Kirov VPN, которая сообщает панели устройство (у каждого в
   `list-users` есть хотя бы одно устройство — иначе он сразу потеряет серверы);
2. сборки подписаны постоянным ключом (раздел 9): со временным ключом каждая новая версия
   приложения выглядит как новое устройство.

```bash
klaus-panel hwid-limit 3                  # 3 устройства на человека
klaus-panel add-user papa --devices 5     # новому знакомому — свой лимит
klaus-panel hwid-limit off                # выключить
```

Поменять лимит уже добавленному человеку или удалить его старый телефон, чтобы освободить
место: панель → «Пользователи» → имя → устройства.

### Переход со старых ключей

- Проще всего поставить VPN-сервер панели на **новый** VPS: старый сервер из `install.sh`
  работает дальше, пока все знакомые не перейдут на подписки.
- На том же VPS `install-node.sh` не запустится, пока работает старый Xray (порт 443 занят).
  Когда все перешли, выполните `sudo MIGRATE=1 PANEL_IP=… SECRET_KEY='…' bash install-node.sh`:
  старый Xray выключится, и старые ключи перестанут работать.
- Ретранслятор из раздела 6 (`install-relay.sh`) работает с одним общим ключом и в подписки
  не входит.
